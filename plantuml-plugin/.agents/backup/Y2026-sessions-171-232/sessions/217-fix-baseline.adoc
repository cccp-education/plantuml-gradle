== Diagnostic

=== Attempt History Tracking (2 FAIL) — cause racine

Les steps inspectent les fichiers d'historique JSON via le regex
`Regex("\"valid\"\\s*:\\s*(true|false)")` — **minuscule `valid`**. Or le
champ réellement émis par le plugin est `"isValid"` (avec un **V
majuscule**). La regex Java/Kotlin étant case-sensitive, elle ne matchait
jamais → collections vides → "Should have at least 1/3 entries".

Vérifié : `/"((?:is)?Valid)"\s*:\s*(true|false)/` → `OK: isValid=false`.

=== RAG Pipeline (1 FAIL) — cause racine

`-Pplantuml.output.rag=<projectDir>/build/plantuml-plugin/generated/rag`
(PlantumlWorld.kt:376). `CollectPlantumlIndexTask` lit
`File(config.output.rag)` = ce chemin `build`. Or le fixture du scénario 3
écrivait dans `<projectDir>/generated/rag` (relatif) → RAG dir introuvable
→ création + early return, jamais le skip attendu.

Mécanique du skip : `shouldReindexPuml(rag-test.puml, promptsDir)` renvoie
false si le prompt `prompts/rag-test.prompt` existe ET que
`ChecksumStore.hasPromptChanged` est false (checksum stocké == courant,
SHA-256 hex minuscule via `%02x`, fichier `<name>.sha256` sur
`build/plantuml-plugin/checksums`).
