:session: 244

:statut: 🟡 EN COURS

== Demande pilote

Les diagrammes PlantUML des articles cheroliv.com ne sont **pas complètement
traduits** : les labels hors guillemets (messages de séquence, activités,
descriptions d'état) restent en français. À l'inverse, quand la traduction
s'applique, elle peut traduire des **termes métier / de code** qui ne doivent
pas l'être (`integer`, `String`, `opencode.json`, `AGENT.adoc`, identifiants,
chemins, options Gradle…). Le but est de conserver l'**idiomaticité** : traduire
quand c'est traduisible, laisser verbatim quand c'est du code ou un terme métier
non traduisible.

== Audit (S-244)

. `contracts.plantuml.PlantUmlBlock.labels()` (N0) ne surface que les labels
  **entre guillemets** et les directives `title/header/footer/caption`. Les
  labels non quotés sont invisibles : `A -> B : texte`, `:texte;`,
  `state X : texte`.
. `PlantumlNoteExtractor` couvre les `note`, pas les messages/activités.
. `PlantumlTranslationPortAdapter` envoie les labels au `TranslationService`
  N0 **sans aucune protection de termes** : le LLM peut traduire `integer` ou
  un identifiant.
. `TextClassifier`/`IdiomaticGlossary`/`NonTranslatableTermRegistry` existent
  côté `plantuml.boundary` riche, mais ne sont **pas** dans le chemin des
  articles (port N0 alimenté par le LLM de l'article).
. Résultat observé : diagrammes partiellement français (messages de séquence,
  activités) et traductions de types/identifiants dans certaines langues.

== Décisions

* **D1 — Périmètre des termes protégés.** Sont protégés : types primitifs et
  types courants (`integer`, `String`, `boolean`, `List<V>`, `Map<K,V>`…),
  jetons de code (fichiers, chemins, URLs, options Gradle, annotations,
  constantes, `snake_case`, identifiants multi-humps, versions, couleurs,
  texte entre backticks), et les termes **enregistrés** (`NonTranslatableTermRegistry`)
  ou **empruntés** (`PlantUmlBlock.borrowedVocabulary`). Les mots de prose
  courants (même `class`/`object` en anglais) restent traduisibles.
* **D2 — Bouclier de termes.** `PlantumlTermShield` remplace chaque terme par
  un placeholder stable `__PLTn__`, puis restaure après traduction. Si le
  traducteur perd un placeholder, le label source est **préservé** (jamais de
  corruption).
* **D3 — Labels non quotés.** `PlantumlProseLabelExtractor` extrait les labels
  de prose non quotés : messages de séquence (`A -> B : texte`), activités
  (`:texte;`), descriptions d'état (`state X : texte`). Les légendes
  (`legend … endlegend`) sont différées (US ultérieure).
* **D4 — Intégration.** `PlantumlTranslationPortAdapter` applique le bouclier
  à chaque label, note et label de prose. Le batching `PlantumlLabelBatch` est
  conservé (les placeholders voyagent dans le texte groupé).
* **D5 — Frontière.** Aucune modification N0 : tout vit dans
  `plantuml.boundary` / `plantuml.repair` (pure domain). Aucun nouveau contrat
  MEMPHIS.
* **D6 — Tests.** Baby-step DDD/TDD/BDD : unit (`PlantumlTermShield`,
  `PlantumlProseLabelExtractor`, port), fonctionnel (port + validateur réel),
  Cucumber (`@plantuml-term-protection`). Local = Build, Tests = CI.
* **D7 — Reprise cheroliv.com.** La re-traduction des diagrammes incomplets est
  une session ultérieure : release plantuml → BOM/catalog → exécution du delta
  ciblé (détecteur de blocs incomplets à ajouter côté site). Aucun run LLM
  metered dans cette session.

== Analyse `bakery-plugin/.agents/i18n_review.adoc` (S-244) — prise en compte

L'audit pilote confirme le diagnostic et **déplace la priorité** : le problème
n'est pas la traduction (le `PlantumlTermShield` est jugé « le meilleur morceau
du dispositif ») mais le **contrat de sortie** — `reportConvergence` mesure le
store (`0 PENDING / 0 cassé`), pas l'artefact publié. C'est un faux vert
(S-269/S-243). Les défauts mesurés au live : sentinelles LLM (30 fichiers),
`toc::[]` traduite (142), `options="header"` perdu (0/21), duplication (4 EN
> 150 %, jusqu'à 9 HI), diagrammes bruts (0108 EN = 9, JA = 17), résidus FR
dans les diagrammes (alt/labels), SEO localisé non câblé, RTL absent.

Décision de séquencement (révisée) :

. **P0.3 — gate rendu diagramme** : zéro `@startuml` brut dans les variantes
  bakées (hors `[source,plantuml]`), σ>0 sur les SVG. Prérequis de toute
  re-traduction (sinon nouveau faux vert).
. **P0.2 — gate langue + sentinelle + preserve-rule** : refus LLM, placeholders
  `__PLT`, macros `toc::`/`include::`/`image::`, `options="header"`.
. **P0.1 — gate intégrité structurelle AST** : squelette variante vs FR
  (tables, macros, ids de diagrammes, sections, ratio de duplication).
. **P2 — contrat N0 `PreserveRule`/`TranslatableRegion`** : convergence
  `SwitcherBlockMask` (bakery), `TextTranslatableClassifier` (document),
  `PlantumlTermShield` (plantuml) sur un seul contrat (seuil à 2).
. **US-5 — re-traduction cheroliv** : release plantuml 0.0.11 → BOM/catalog
  → run delta ciblé, **uniquement après P0.3/P0.2**, et vérifiée par les gates.

Conséquence immédiate : **aucun run LLM metered dans cette session** ; US-5
reste ⏳ et sera exécutée dans une session dédiée (release + gates).
